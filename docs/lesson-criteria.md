# 골고 폼: 지표 체계 큰 설계

> 골고와 별개 프로그램이다(2026-11-27 사용자 결정, [lesson-build.md](lesson-build.md) 0절).

2026-11-27 정리. 개인 레슨·훈련 영상(고정 카메라 한 대)으로 자세와 기술을 재고 점수와 고칠 점을 보여 주기 위한 구조다.
동작(드리블, 슈팅 …)은 이 구조 위에 하나씩 끼워 넣는다. 첫 동작은 드리블.

## 0. 원칙
- **동작 하나부터 끝까지**: 분류표를 먼저 넓히지 않는다. 동작 하나를 ①~⑥까지 완성하고 다음 동작으로 간다.
- **기준이 먼저**: 지표는 "잘하는 동작은 어떻게 하나"에서 나온다. 근거가 없는 지표는 점수에 넣지 않고 "참고"로만 보여 준다. 숫자를 지어내지 않는다.
- **기준표는 코드와 분리**: 동작 정의(③)·지표(④)·기준(⑤)·고칠 말(⑥)은 데이터 파일로 두고, 분석 코드는 그 파일을 읽어 동작한다. 기준을 고치면 점수가 바로 바뀐다.
- **골고와 따로**: 골고 경기 분석과 코드·저장을 섞지 않는다. 같은 6층 생각은 경기 분석에도 맞지만, 연결이 필요해지면 내보내기 파일로만 잇는다.
- **카메라 한 대의 한계를 적는다**: 화면과 나란한 면의 움직임은 정확하고, 카메라 쪽 깊이는 추정이다. 지표마다 찍는 각도와 믿음도를 함께 적는다.

## 1. 전체 흐름

```
영상 (고정 카메라 한 대)
  │  자세 모델(관절 좌표) + 공 찾기
  ▼
① 기본 측정값   매 장면 바로 나오는 숫자
  ▼
② 사건          특정 순간 찾기 (볼터치, 걸음, 디딤, 임팩트 …)
  ▼
③ 동작·단계     사건 순서로 동작을 자르고 단계로 나눔
  ▼
④ 지표          단계마다 ①을 재서 만든 숫자 (속도·퍼포먼스·자세 세 축)
  ▼
⑤ 기준과 점수   잘하는 동작 자료와 비교해 0~100
  ▼
⑥ 피드백        점수 낮은 지표 → 고칠 말 + 그 장면, 지난번 대비 변화
```

## ① 기본 측정값
모든 동작에 공통. 관절 좌표(처음엔 MediaPipe Pose 33점, 발뒤꿈치·발끝 포함)와 공 위치로 장면마다 계산한다.

**좌표와 단위**
- 화면 좌표(px)를 그대로 쓰지 않는다. 길이는 **키 비율**(엉덩이~발목 길이 기준) 또는 **m**(공 지름 22cm, 또는 간격을 아는 콘 두 개로 환산)로 바꾼다.
- 각도는 도(°). 화면 평면 안의 각도다.
- 좌우 구분: 왼발·오른발은 관절 좌표의 좌우로 정한다. 카메라 쪽에서 가려진 다리는 그 장면 값을 비워 둔다(지어 채우지 않음).
- 장면마다 관절 신뢰도를 함께 저장하고, 낮으면 그 값은 빈칸.

| 묶음 | 이름 (id) | 뜻 |
|---|---|---|
| 몸 | 몸통 앞뒤 기울기 `trunk_pitch` | 엉덩이 중심→어깨 중심 선이 수직에서 앞뒤로 기운 각 (옆에서 찍을 때) |
| 몸 | 몸통 좌우 기울기 `trunk_roll` | 같은 선이 좌우로 기운 각 (정면에서 찍을 때) |
| 몸 | 어깨선 기울기 `shoulder_tilt` | 두 어깨를 잇는 선의 수평 대비 각 |
| 몸 | 무릎 굽힘 `knee_flex_l/r` | 엉덩이-무릎-발목 각을 180°에서 뺀 값 |
| 몸 | 엉덩이 굽힘 `hip_flex_l/r` | 어깨-엉덩이-무릎 각을 180°에서 뺀 값 |
| 몸 | 무게 중심 높이 `com_h` | 엉덩이 중심 높이 ÷ 선 키 (낮을수록 자세가 낮음) |
| 몸 | 무게 중심 위치 `com_base` | 엉덩이 중심이 두 발 사이(지지면) 안에 있는지, 벗어난 거리 |
| 몸 | 고개 숙임 `head_pitch` | 코·귀 위치로 본 고개 숙인 정도 (헤드업 판단) |
| 몸 | 팔 벌림 `arm_span` | 두 손목 사이 거리 ÷ 어깨 너비 |
| 발 | 발 위치·속도 `foot_pos_l/r`, `foot_v_l/r` | 발끝·발뒤꿈치 위치와 속도 |
| 발 | 발 착지 여부 `foot_contact_l/r` | 발이 땅에 닿아 있는지 (높이·속도로 판단) |
| 이동 | 몸 속도·가속 `body_v`, `body_a` | 엉덩이 중심의 속도와 가속 |
| 이동 | 이동 방향 `body_dir` | 속도 방향 (방향 전환 판단) |
| 공 | 공 위치·속도 `ball_pos`, `ball_v` | 공 중심 위치와 속도 |
| 공 | 발과 공 거리 `foot_ball_d` | 가까운 발끝과 공 중심 거리 |
| 공 | 몸과 공 거리 `body_ball_d` | 엉덩이 중심과 공 중심의 앞뒤 거리 |

새 동작에 필요한 값이 생기면 이 표에 더한다. ①은 모든 동작이 같이 쓴다.

## ② 사건
①의 값이 바뀌는 순간을 찾는다. 사건마다 시각(장면 번호)과 관련 발(왼·오른)을 남긴다.

| 사건 | 찾는 방법 (처음 버전) |
|---|---|
| 걸음 `step` | 발 착지 여부가 떨어짐→닿음으로 바뀐 순간 |
| 볼터치 `touch` | 발과 공 거리가 가장 가까워지고 공 속도·방향이 바뀐 순간 |
| 디딤 `plant` | 차기 직전 마지막으로 착지한 반대발 |
| 임팩트 `impact` | 차는 발과 공이 가장 가깝고 직후 공 속도가 크게 늘어난 순간 |
| 방향 전환 `cut` | 이동 방향이 일정 각도 이상 바뀐 구간의 가운데 |
| 멈춤 `stop` | 몸 속도가 거의 0이 된 순간 |

사건 찾기가 틀리면 그 뒤가 다 틀린다. 동작마다 사람이 표시한 정답 몇 개와 맞춰 보는 시험을 둔다(⑤ 시험 참고).

## ③ 동작·단계
동작은 "어떤 사건이 어떤 순서로 나오면 이 동작이고, 단계는 어디서 끊는가"로 정의한다.

**동작 정의 칸**
| 칸 | 뜻 |
|---|---|
| 동작 이름 | 예) 8자 드리블, 인스텝 슈팅 |
| 훈련 방식 | 콘 배치, 거리, 반복 횟수 (같은 방식으로 찍어야 비교가 됨) |
| 찍는 자리 | 카메라 위치·높이·거리·각도 (그림 포함) |
| 시작·끝 | 동작 구간을 여는 사건과 닫는 사건 |
| 단계 | 단계 이름과 경계 사건 |

**예 (자세히 채우는 것은 동작별 문서에서)**
- 인스텝 슈팅: 접근(임팩트 전 마지막 3걸음) → 디딤(`plant`) → 임팩트(`impact` 앞뒤) → 마무리(임팩트 뒤 0.5초)
- 드리블: 터치 → 이동 → 다음 터치의 반복, 방향 전환 구간(`cut` 앞뒤)

## ④ 지표
지표 하나는 "**어느 동작**의 **어느 단계**에서 **어떤 기본 측정값**을 **어떻게** 잰다"로 정의한다.
"어떻게"는 순간값(사건 순간), 구간 평균, 구간 최대·최소, 변화량, 횟수·비율 중 하나.

**세 축** (모든 동작이 같은 세 축을 쓴다. 갤로핑 8round와 같은 틀)
- **속도**: 얼마나 빠르고 정확한가 (평균·최고 속도, 정확도)
- **퍼포먼스**: 공을 얼마나 잘 다루나 (볼터치, 잔발, 탄력성, 리듬)
- **자세**: 몸을 어떻게 쓰나 (상체 밸런스, 헤드업, 무게축, 디딤발)

**지표 정의 칸**
| 칸 | 뜻 | 예 |
|---|---|---|
| id | 지표 이름 | `shot.plant.knee_flex` |
| 이름 | 화면에 보일 이름 | 디딤 무릎 굽힘 |
| 동작·단계 | 어디서 재나 | 인스텝 슈팅 · 임팩트 |
| 계산 | 어떤 ①을 어떻게 | 디딤발 `knee_flex` 의 임팩트 순간값 |
| 축 | 속도 / 퍼포먼스 / 자세 | 자세 |
| 단위 | ° / m / 키 비율 / 초 / 회 / % | ° |
| 찍는 각도 | 이 값이 맞게 나오는 방향 | 옆 |
| 믿음도 | 높음 / 보통 / 참고 | 높음 |
| 기준 | ⑤의 기준 id | `ref.shot.plant.knee_flex` |
| 고칠 말 | ⑥에서 쓸 말 | 범위 아래·위 각각 한 줄 |

**믿음도**
- 높음: 화면 평면 안의 값, 관절이 잘 보임. 점수에 넣는다.
- 보통: 깊이 영향이 조금 있거나 30fps로는 흐린 값. 점수에 넣되 비중을 낮춘다.
- 참고: 카메라 한 대로는 믿기 어려운 값. 숫자만 보여 주고 점수에는 넣지 않는다.

## ⑤ 기준과 점수

**기준 자료** (믿을 만한 순서)
1. **코치 시범**: 같은 카메라·같은 자리·같은 훈련 방식으로 찍은 코치 동작. 조건이 같아 가장 정확하다. 레슨마다 쌓는다.
2. **공개 프로 동작 자료**: 프로 선수 동작의 관절 좌표 공개 자료(예: 프로 경기 슈팅 자세 3DSP, 여자 프로 페널티킥 133개 관절 좌표). 분포("프로는 이 구간에 몰려 있다")를 만든다. 찍은 각도가 달라 각도 지표는 조심해서 쓴다.
3. **연구 값**: 스포츠 과학 논문의 측정값(예: 인스텝킥 무릎 펴는 속도와 킥 거리 관계).
4. **내 최고 기록**: 기준이 없을 때 "내 최고 대비"만 보여 준다(점수에는 안 넣음).

유튜브 영상을 내려받아 기준 자료로 쓰지 않는다(약관).

**기준 정의 칸**
| 칸 | 뜻 |
|---|---|
| id | `ref.…` |
| 좋은 범위 | 아래·위 경계 [lo, hi] |
| 허용폭 | 범위를 벗어난 뒤 점수가 0이 되는 거리 t |
| 근거 | 자료 이름·출처·표본 수·찍은 각도 |
| 날짜 | 언제 정한 값인지 (자료가 쌓이면 바뀜) |

**점수 계산 (처음 버전, 단순하게)**
- 지표 점수: 범위 안이면 100. 벗어난 거리 d 이면 `100 × max(0, 1 − d / t)`.
- 분포 기준(프로 자료)이면 범위 = 분포의 25~75%, 허용폭 = 분포 표준편차의 2배로 시작한다.
- 축 점수 = 그 축 지표 점수의 평균(믿음도 보통은 절반 비중). 동작 점수 = 세 축 평균.
- 잰 지표가 빠지면 평균에서 빼고 "몇 개 중 몇 개 잼"을 함께 보여 준다.
- 반복한 동작(슈팅 10번 등)은 회마다 점수를 내고 중앙값과 가장 좋은 회를 함께 보여 준다.

**시험 (기준이 맞는지)**
- 같은 동작을 잘한 것과 일부러 틀리게 한 것으로 찍어, 그 지표 점수가 실제로 갈리는지 본다. 안 갈리면 빼거나 고친다.
- 사건 찾기(②)는 사람이 표시한 정답과 시각 차이를 잰다.
- 분석기의 IDF1 시험처럼 결과를 차수로 기록한다.

## ⑥ 피드백
- 동작 점수, 세 축 점수, 지난번 대비 변화(비포·애프터), 회차별 추이 그래프.
- 점수가 가장 낮은 지표 2~3개: 고칠 말 + 그 순간 장면(관절 선 겹침, 느리게 보기).
- 코치 시범이 있으면 동작 순서에 맞춰 나란히 놓고 관절 각도 차이를 표시한다.
- 고칠 말은 기준표에 미리 써 둔다(범위 아래일 때, 위일 때 각각). 지어낸 조언을 만들지 않는다.

## 7. 저장 (처음 버전)
- 기준표(③ 동작 정의, ④ 지표, ⑤ 기준, ⑥ 고칠 말): 저장소 안 데이터 파일(JSON). 위치는 첫 동작 구현 때 정한다.
- 레슨 결과: 영상별 ①·② 원재료(나중에 기준이 바뀌면 다시 계산), ④ 지표값, ⑤ 점수. 내 드라이브 "골고폼/" 폴더(자세한 구조는 lesson-build.md 8절).
- 처음에는 본인만 본다. 공개 범위는 나중에.

## 8. 촬영 규칙 (공통)
- 고정 카메라 한 대(공기계 Z 폴드3 + 삼각대 또는 반 접어 세우기), 몸 전체와 공이 다 나오게 5~10m.
- 동작마다 정해진 자리·각도(③ 찍는 자리). 매주 같은 자리에 지난 화면을 반투명으로 겹쳐 맞춘다.
- 차기가 있는 동작은 슬로모션(120fps)을 권장. 30fps도 분석은 되지만 속도·임팩트 지표의 믿음도가 내려간다.
- 크기 기준: 공(지름 22cm). 간격을 아는 콘 두 개를 두면 더 정확.

## 9. 참고: 갤로핑
- 8round(드리블): 카메라 4대 + Halpe26 관절 + 삼각측량으로 3D. 지표 12개 중 공개된 이름은 속도(평균·최고 속도, 정확도), 퍼포먼스(볼터치, 잔발, 탄력성), 자세(상체 밸런스, 헤드업, 무게축). 진단 → 50분 교정 → 다시 측정 → 비포·애프터·성장률.
- 특허 KR 102963689 B1(데이터 기반 선수 수행 능력 분석과 성장 가능성 예측): 관절 위치 변화 → 항목별 평가 기준값과 비교해 점수. 자세에서 뽑는 것은 밸런스, 무게 중심, 무게축, 디딤발과 이동, 시선, 뒤꿈치, 중심축 이동, 스텝 수, 팔·무릎·다리·상체 각도. 기준값 숫자는 공개되지 않았다.
- 골고 폼은 카메라 한 대라 2D가 기본이다. 갤로핑 값이 있어도 그대로 맞지 않으므로 기준은 직접 만든다.

- 성인 아마추어 기준값은 드물다(슈팅·달리기만 있음). 나머지는 유소년·프로 유스·엘리트 값을 "참고선"으로 쓰고 화면에 대상을 표시한다.
