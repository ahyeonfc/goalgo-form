# 골고 폼: 자유 분석과 코칭

2026-11-27 첫 판(0.3.0). 찍은 영상만 넘기면 구간마다 무슨 동작인지 알아채고, 잘한 점·고칠 점·오늘의 연습·찍는 팁을 보여 준다.
도전 모드([challenge.md](challenge.md))는 코드는 두고 처음 화면에서만 숨겼다(사용자: 자유 분석 먼저).

## 흐름
```
영상 → 장면별 관절(MediaPipe Pose full) + 공(EfficientDet-Lite2, 사람 주변 확대 한 번 더)
     → 손질(화면 밖 관절·튀는 공 버림, 빈칸·흔들림·좌우 뒤바뀜) → ①측정값 → 슬로모션 보정 → ②사건
     → 자세 믿음 검사 → 구간 알아채기 → 구간별 지표 → 코칭
```

## 자세 믿음 검사
- 공 지름 ÷ 화면 속 키가 0.25 를 넘으면(실제는 약 22/키 ≈ 0.13) 몸 전체가 안 보여 자세 모델이 몸을 지어낸 것으로 본다. 코칭을 하지 않고 "머리부터 발끝까지 3~4m" 안내만 한다.
- 발견 과정: 샘플 7187047(허리 아래만 찍힘)에서 MediaPipe 가 화면 위에 어깨·코를 지어내 키가 실제의 1/3 로 잡혔다. 5449931(발 확대)도 같음.
- 크기(화면 속 키) 기준 순서: 몸통(어깨~엉덩이 = 0.288H) → 정강이(무릎~발목 = 0.246H) → 공 지름(22cm). 비율은 Drillis·Contini(Winter 인용).

## 구간 알아채기 (우선순위 순)
| 동작 | 규칙(첫 판) |
|---|---|
| 리프팅 | 공이 내려오다 다시 올라가는 가장 낮은 점이 바닥보다 위 + 몸 부위(발·무릎·머리) 가까이. 이어진 닿음 3번 이상 |
| 패스·슈팅 | 임팩트(터치 뒤 공 속도가 2배 넘게 빨라짐). 공 속도 15m/s 이상이거나 20° 넘게 뜨면 슈팅 |
| 공 다루기 | 몸이 거의 제자리(0.6키/초 아래). 토 탭 = 발이 바닥에서 떠 공 위에 닿음, 당기고 밀기 = 터치 뒤 공이 몸 쪽(당기기)·바깥(밀기). 8번 이상 |
| 드리블 | 터치가 1.5초 안 간격으로 4번 이상 + 몸이 움직임 |

## 코칭 근거 (지어내지 않음)
1. **같은 영상 안 비교** — 기준 없이도 공정: 왼발 대 오른발 박자·터치 크기·공 높이, 앞 절반 대 뒤 절반 빠르기, 발 드는 높이.
   - 장면 간격의 2.5배(30fps 0.08초)보다 작은 차이는 재는 오차라 지적하지 않는다.
   - 터치 시각은 공 가로 속도 부호가 바뀐 순간으로 다듬는다(발-공 최소 거리는 발이 들어오는 방향에 따라 밀림).
2. **연구 기준** — 출처 있는 값만: 드리블 초당 터치(Zago 2016: 빠른 3.0, 느린 2.3), 디딤발 공 뒤 0~15cm(Scurr 2009·Hay 1993), 디딤발 옆 27~37cm(Ou 2023), 디딤 무릎 임팩트 약 40°(Sinclair 2014), 공 속도(아마추어 약 25, 세미프로 26m/s), 접근 2~5걸음.
3. **내 지난 기록** — 같은 동작 최근 3개 평균 대비.
- 고칠 점은 심한 순으로 2개까지. 각 항목에 근거 종류를 적고, 장면 사진·"이 장면 보기"를 붙인다.

## 결과 화면
요약(알아챈 동작, 잘한 점·고칠 점 개수, 몸·공 찾은 비율) → 동작별 코칭 카드(숫자, 👍, 🔧, 🏋️ 오늘의 연습, 📱 다음 찍는 팁) → 관절 선 다시 보기(영상 위에 몸통 초록·왼쪽 파랑·오른쪽 주황, 공 노랑, 터치 띠 누르면 그 순간, 느리게) → 장면 → 메모.
- 영상은 복사해 두지 않으므로, 앱을 다시 열면 "갤러리에서 같은 영상 다시 고르기"로 겹쳐 본다.

## 샘플 영상 시험 (Pexels 무료 영상, 클라우드 CPU)
- 받은 샘플: 리프팅 5449928·6078265·10349012·11271460·10349053, 공 다루기 7187047·5449931(둘 다 몸이 잘림), 드리블 7187049·7187061, 차기 3192082·6084023.
- 첫 결과(EfficientDet-Lite0, 확대 없음): 공 찾은 장면 3~22%(드리블), 리프팅 47~99%. 10349012 는 바닥의 다른 공을 집어 리프팅을 못 알아챔.
- 고침: Lite2 + 사람 주변 확대 + 몸 가깝고 앞 장면과 이어지는 공 고르기. 결과는 아래 "시험 기록".

### 2차 (2026-11-27) — 정답 대비(장면을 직접 보고 표시)
- 10349012 정답: 닿음 6번(약 0.8·1.8·3.0·3.9·4.9·5.9초, 대부분 왼발). 엔진: 1차 1/6 → 기준 다듬기 4/6 → 슬로모션·몸 잘림 보정 뒤 개수 6/6(시각 일치는 4~5/6).
- 발견: 광고용 샘플은 슬로모션이 많다. 시간 기준 판정이 다 어긋났음.

### 3차 (2026-11-27) — 슬로모션 보정(engine/timescale.js)
- 날아가는 공(몸에서 키의 0.12배 넘게 떨어짐, 6장 이상)에 포물선을 맞춰 세로 가속도 a(키/초²) → k = √(g/2a), g = 9.8 ÷ 키(m). 날아가는 구간 2개 이상, k ≥ 1.6 이면 슬로모션으로 보고 실제 시각으로 다시 분석, 결과 시각은 영상 시각으로 되돌림.
- 잰 배율: 19310016 3.5배, 5449928 1.9배, 10349012 1.65배, 6078265 1.4배(기준 아래, 보통으로 봄). 원근·키 추정 오차로 ±40% 흔들릴 수 있어 기준을 1.6으로 넉넉히 잡음.
- 결과: 19310016 토 탭(틀림) → 리프팅 7번, 5449928 최고 연속 5 → 6, 10349012 6번.
- 거의 수직으로 뜬 공(60° 넘음)은 차기가 아니라 리프팅 띄우기로 봄(15187502 가 슈팅으로 잘못 잡히던 것).
- 72개 샘플 중 개인 훈련 분석에 쓸 만한 것은 일부(여러 사람·먼 경기 장면·낮은 화질 426×240 이 많음).

## 남은 일
- 공 찾기: 축구공 전용 감지기(경기 분석기 YOLO26s 사본 ONNX)로 바꾸기. 드리블·작은 공에서 효과가 클 것.
- 직접 찍은 영상으로 규칙 숫자 맞추기(정답 표시 도구, lesson-build.md 7절).
- 패스·슈팅: 120fps 실제 영상으로 공 속도·디딤발 검증, 목표 맞힘 입력.
- 샘플 대량 수집(Pexels API 열쇠 발급 중단 → 검색으로 모음).

## 공 찾기 모델 비교 (2026-11-27, RF-DETR)
- 샘플 13개, 영상마다 고르게 40장(모두 520장). EfficientDet-Lite2(960px 전체 화면, 앱의 1차와 같음, 문턱 0.3) 대 RF-DETR Nano(384px 전체 화면, 문턱 0.4).
- 공을 찾은 장면: EfficientDet 208/520(40%), RF-DETR 406/520(78%). 둘 다 찾은 208장 중 198장(95%)이 같은 자리.
- RF-DETR 만 찾은 장면을 눈으로 확인: 가까운 큰 공(EfficientDet 이 놓침), 콘 옆의 먼 작은 공 모두 맞음. 공 없는 신발 클로즈업은 0.03 으로 안 잡음.
- 8비트로 줄인 모델(34MB): 400/520 찾음, 원본과 같은 자리 388. 데스크톱 CPU 약 100ms/장(폰은 더 느림) → 앱은 EfficientDet 두 번(전체·확대)으로 못 찾은 장면에만 돌림.
- 라이선스: RF-DETR Nano 는 Apache-2.0(상용 가능). 경기 분석기 YOLO26s 는 AGPL 이고 드라이브에만 있어 이번엔 쓰지 않음.
